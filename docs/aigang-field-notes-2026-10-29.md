# AI Gang field notes: Gonq mobile build, 2026-10-29/30

Written by Claude (claude-operator, mobile build orchestrator).
These are AI Gang mechanics problems found while building Gonq's mobile stories (plan: `docs/gonq-mobile-stories-2026-10-29.md`).
No change was made to the AI Gang repository; the only local change is listed under "Local changes".

## Findings

| # | Problem | Mechanism | Seen on | Workaround used | Suggested upstream fix |
|---|---|---|---|---|---|
| 1 | Refinement says sibling subtasks share **one** branch/PR, but each agent opens its own PR | The refinement agent wrote "All three subtasks land on ONE branch/PR targeting dev, committed in this order: Backend, then Frontend, then DevOps". Each dev agent's definition creates its own branch and PR, and the dispatch gate frees the next subtask only after the previous one merges, so a shared branch can never happen. | M-01 (PRs #227, #229, #231), M-02, M-03 | Accepted sequential PRs; each was verified on its own and the story was verified as a whole. | Refinement should not prescribe branch layout; or the platform should support one PR per story explicitly. |
| 2 | Sibling subtasks of one story run in parallel by default, though their PRs depend on each other | The per-role gate (`dispatch-limits.json`) lets a backend, a frontend and a devops subtask run at once. For a repo-wide move (workspace conversion) or a backend change the frontend consumes (generated bindings), the later halves need the earlier merge. | M-01, M-03 | `dispatch-limits.json` set to `{}` (one implementation item in flight, project-wide), so siblings ran in merge order. | Let refinement express "blocks" between its own subtasks, and gate on it. |
| 3 | A Jenkinsfile Groovy compile error gives the agent no signal | Jenkins failed before any stage (`WorkflowScript: 289: unexpected char: '\'`), so the pipeline's failure-comment step never ran. The agent's session had ended with `completed`, so the item would have sat `in-progress` forever. | PR #227 build #2 | Posted the error text on the work item and re-readied it. | Report a pipeline that fails to load (no stage ran) on the work item, like any other PR-build failure. |
| 4 | Agents cannot read Jenkins or the Actions logs Jenkins waits on | The Jenkins failure comment carries no log excerpt; agents get 403/connection refused on Jenkins. Failures seen: a TS2307 in the Rust-checks frontend build, a Rust contract test panic, a macOS-only duplicate `_EMBED_INFO_PLIST` symbol. | PRs #227, #232, #234 | Posted the failing lines (test name, panic text, file:line) on the work item each time. | Include the failing step and its last error lines in the Jenkins failure comment. |
| 5 | The session reaper marks a healthy item `failed` | The agent reported `completed` when it opened the PR. Jenkins' failure comment re-dispatched it; it pushed the fix (4560c6c) and ended without a new report (it had nothing new to report). The reaper resumed it twice, then reported `failed` ("ended_without_report"). The `failed` status also freed the dispatch slot, so the dependent frontend subtask started before the backend PR merged. | 6e6ff61d (PR #234) | Comment explaining the false failure; `failed` -> `in-progress`; the PR merged on its next build. | Treat "already reported completed with a PR that is still open" as reported; don't count `failed` from the reaper as leaving flight. |
| 6 | Agents edit files outside their subtask's scope | The backend agent fixed the Jenkinsfile and workflows (devops' scope); the frontend agent fixed the Dockerfile (devops' scope) after the Beta image broke. The outcomes were right; the split was not followed. | PRs #227, #230 | Logged as process-only, no rework. | Either drop strict per-role scopes for repo-wide stories or have refinement make one subtask. |
| 7 | A merge can break Beta while its PR build is green | The PR build does not build the Beta Docker image, so a Dockerfile that missed the workspace `package.json` files (`tsc: not found`) passed the PR and failed only the post-merge deploy (dev #215). | PR #229 | Fixed by the frontend agent in PR #230 from Jenkins' failure comment. | Build the Beta image (no push) in the PR build when the Dockerfile or package manifests change. |
| 8 | A cancelled blocker blocks its dependent forever, and the operator account cannot remove the link | Core refuses `ready` while any `blocks` blocker is not `done`, and a `cancelled` blocker never counts as done. claude-operator has no delete permission on work-item links (admin delete page 403), so a story deferred after filing (M-08) leaves its dependent (M-09) gated. | M-08 -> M-09, link 1d42e70c | Reported to the owner; the link waits for gonq-admin. | Count `cancelled` blockers as resolved, or allow the operator to remove links it created. |
| 9 | Criteria that name a literal grep can be wrong about the code's spelling | M-03's `grep -rn "invoke("` misses `invoke<...>(`, so the check as written proves nothing; the substance passed on reading. | M-03 | Logged as wording-only. | Write criteria as outcomes, with the check as an example. |
