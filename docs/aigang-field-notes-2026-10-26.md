## Proposal: project map in the artifact store

**Problem.** The project map every agent reads first is a git-tracked prose section of CLAUDE.md, edited by most PRs. It is the single largest source of merge conflicts and blocks safe parallel agents.

**Step 1 (in Gonq, local change 6).** The source of truth moves into the code: each source file starts with a header comment saying what it is for. A script (`npm run map`) generates an untracked `PROJECT_MAP.md`; `npm run map:check` fails the PR build when a header is missing; `--json` emits `[{path, summary}]`. Concurrent PRs only touch their own files' headers, so the map adds no conflict surface, and it is always in sync with the checked-out tree.

**Step 2 (AI Gang).** Store the map in the artifact store and move reads and writes onto Streams:
- *Single writer:* the post-merge dev build (or core on `beta_deployed`) runs the generator with `--json` for the merged SHA and publishes the entries through a Streams command. One writer, ordered by the stream: no concurrency problem.
- *Keyed entries:* one record per (project, path), stamped with the merged SHA. This needs service-writable artifacts, per-key writes with a version or ETag, change events, and list/query by project. Today artifacts are whole files, uploaded by humans, last-write-wins, without listing.
- *Read path:* the librarian delivers a read-only rendered map into each session at dispatch. A branch session can still run the generator locally to see its own new files.
- *Trade-offs:* the store becomes a cache of dev, never the source, so it cannot drift or block a merge. Humans keep the in-repo headers and `npm run map`; the store adds cross-repo sharing and a map without a checkout.
- *Migration:* seed from the generator's `--json`; both paths coexist.
