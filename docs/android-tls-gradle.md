# Android: token store and TLS verifier (M-10)

Status: the Rust side is in (`AndroidStore` in crates/gonq-core, `android_tls::init` in apps/mobile/src-tauri). Both are
UNVERIFIED on a device until M-13. The Gradle half landed with M-09 (`apps/mobile/src-tauri/gen/android`, generated by `tauri android init`).

## What M-09 added to the generated Gradle project

Done in `apps/mobile/src-tauri/gen/android/app/build.gradle.kts` (the template is Kotlin DSL, so the crate README's `.gradle.kts`
variant): the Maven repository (restricted to group `rustls`), a `RustlsVersion` value source that reads the version of
`rustls-platform-verifier-android` from the repo's `Cargo.lock` (0.2.0 today, so it tracks the lock file), and
`implementation("rustls:rustls-platform-verifier:<that version>")`. The proguard keep rule is in `app/proguard-rules.pro`.

The open question is resolved: `Cargo.lock` is `../../../../../../Cargo.lock` relative to the `app/` directory (app, android, gen,
src-tauri, mobile, apps, repo root). Two deliberate differences from the README snippet: the dependency is declared with the
version directly instead of through `resolutionStrategy`, because the README matches group `org.rustls` while the artifact it
asks for is group `rustls`, so that rule would never fire. UNVERIFIED on a device until M-13.

If `tauri android init` is ever re-run, re-apply these edits.

## Assumptions in the Rust code

- `ndk-context` is initialised by Tauri's runtime (tao 0.37.1 `onCreate` calls `ndk_context::initialize_android_context` with
  the JavaVM and the application Context before `run`). Checked in the source, not on a device. If it were not, the
  Keystore store reports `Unavailable` (session-only) and the verifier init is skipped with a log line.
- android-native-keyring-store 1.0.0 reads that context through `ndk-context`, so no Java-side `Keyring.initializeNdkContext`
  call is made.

## Behaviour to keep in mind

- Android Keystore entries **do not survive an uninstall** of the app. The UI must not promise a sign-in outlives a reinstall.
- `github_status` is unchanged (`storage: "keychain" | "session_only" | null`); an unavailable Keystore falls back to session only.
- `keychain_selftest` (debug builds only, in gonq-mobile) round-trips a dummy entry under account "selftest" and returns
  `{ store, round_trip, error }`; it never touches the real token.
