# gonq — Project Map

## Framework / Runtime
Tauri 2 desktop app (Rust) with a React 18 + TypeScript + Vite 5 frontend and a CodeMirror 6 editor. Node 22.

## Key Directories
The per-file map is generated, not written here: run `npm run map` and read PROJECT_MAP.md (gitignored, one line per
source file, taken from each file's header comment). `npm run map -- --json` prints the same as JSON.

- apps/desktop/ — the npm workspace for the desktop/web app (@gonq/desktop; root package.json `workspaces: [apps/*, packages/*]`, one package-lock.json and node_modules at the root; its own package.json holds the frontend deps and the dev/build/test/test:e2e/tauri scripts, and index.html, vite.config.ts, tsconfig.json, tailwind/postcss configs, components.json and playwright.config.ts live here). Root `npm test` and `npm run build` fan out to the workspaces; `npm run tauri ...` runs from apps/desktop. Paths below without a prefix are relative to apps/desktop/ (src/ entries) or, where marked `@gonq/editor`, to packages/editor/.
- src/            — React + TypeScript desktop shell: App.tsx, components/ (RepoNavigator = the navigator's GitHub root; MenuBar.tsx; ui/ = shadcn/ui primitives themed by CSS vars in the package's styles/tokens.css), dialogs/dialogs.tsx (registers every app dialog), lib/utils, testing/renderApp.tsx (the App-level test harness), styles/index.css (imports the package's tokens.css and editor.css), and the App-level tests of the package's features (src/features/**, src/commands/shortcuts.test.tsx), which need App/MenuBar/renderApp and so stay here. Everything shareable lives in packages/editor and is imported as `@gonq/editor/<subpath>` (see below).
- packages/editor/ — the npm workspace `@gonq/editor` (private, consumed as TypeScript source by apps/desktop; the `exports` map in its package.json lists every subpath, add one when a new module or tsx file must be imported from outside; its own vite.config.ts/tsconfig.json/src/setupTests.ts run its tests: jsdom, `css: { include: [/editor\.css/] }`). Nothing in it may import from apps/desktop. src/: editor/ (the one CodeMirror 6 editor; formatTools.ts/tableTools.tsx = the FORMATS/TOOLS action tables shared by the desktop toolbars and the Format menu), model/ (pure formatting, toc, outline, threads, newThread logic), document/ (open tabs), commands/ (the command registry: defineCommand/defineMenu, CommandContext; index.ts auto-loads features), features/ (one folder per menu feature, each index.ts registers its commands; features/github/ = Open Repo/Open PR (sign-in itself runs inside the Settings dialog: components/SettingsDialog.tsx + GitHubSignInPanel.tsx in the desktop app), the in-memory session branch list sessionBranches.ts and the scripted PR title/body defaults prDefaults.ts), dialogs/DialogHost.tsx (registerDialog/openDialog/<DialogHost/>), platform/ (native/web boundary and the generated bindings.ts; github.ts is the only caller of the github_* commands and owns the github:// path format, which routes files.ts/folders.ts to GitHub the way ssh:// goes to remote.ts), comment-threads/ (Markdown comment-threads library, barrel in index.ts), agent-skill/ (bundled SKILL.md), lib/ (theme, useTheme), testing/ (editor.ts and mockBindings.ts test helpers), styles/ (tokens.css, editor.css).
- crates/gonq-core/ + apps/desktop/src-tauri/ — Cargo workspace (root Cargo.toml, one Cargo.lock/target at the root). gonq-core: github/, ssh/, settings, recents, folder and the shared command list (commands.rs); desktop: Tauri shell (lib.rs `run`), tauri.conf.json, capabilities, icons.
- e2e/            — (apps/desktop/e2e) opt-in Playwright Chromium tests against the web build (`npm run test:e2e`; playwright.config.ts builds + serves via vite preview; needs `npx playwright install chromium`; excluded from vitest, not run by Jenkins)
- scripts/        — repo tooling (project-map.mjs: `npm run map` / `npm run map:check`; check-boundaries.mjs: `npm run boundaries:check`, part of `npm test`, fails on a relative import that crosses a workspace boundary in either direction)
- docs/           — design notes and specs (not shipped); github-review.md is the user-facing guide to the GitHub review flow
- .github/workflows/ — build-desktop.yml (workflow_dispatch with `sha`, dispatched by Jenkins only), rust-checks.yml (workflow_dispatch with `sha` + `request_id`; cargo test + clippy -D warnings, plus on the ubuntu leg a bindings drift check (`cargo test -p gonq export_bindings` then `git diff --exit-code` on packages/editor/src/platform/bindings.ts, the generated FE/BE command contract) and a no-SSH check (`cargo test -p gonq-core --no-default-features`, then `cargo tree -p gonq-core --no-default-features -e normal` must list no russh, russh-sftp or ssh2-config; a separate `android` job, ubuntu, runs `cargo check -p gonq-mobile --target aarch64-linux-android` and the same no-SSH tree check, and skips (logged) until the gonq-mobile crate exists (M-06)), runs as a matrix on GitHub-hosted ubuntu-22.04, windows-latest and macos-latest runners, not on Jenkins; dispatched and awaited by the Jenkinsfile `Rust checks` stage on PR builds to dev, which skips (logged) unless the PR changes a file matching `^(crates/|apps/[^/]+/src-tauri/|Cargo[.]toml$|Cargo[.]lock$)`, and fails on any GitHub API/dispatch error) and release-desktop.yml (`v*` tag push, tagged by Jenkins only); never add other triggers or run/tag by hand
- assets/        — logo sources (OUTLINE = FULL with text as paths, MICRO for 16/24px), render-icons.js that builds apps/desktop/src-tauri/icons, preview/ PNG renders
- apps/desktop/dist/ — web build output (gitignored); served by nginx in the Dockerfile for beta

## Entry Points
- apps/desktop/index.html → apps/desktop/src/main.tsx → apps/desktop/src/App.tsx
- apps/desktop/src-tauri/src/main.rs → lib.rs (`run`)

## Conventions
- `npm run dev` is the web dev loop (port 1420); `npm run build` type-checks then builds the web frontend.
- `npm run tauri build` makes the native bundle (nsis/dmg/appimage, unsigned). Updater is disabled.
- Beta deploys the web build (Dockerfile → nginx). Jenkinsfile follows /agent-docs template; don't hand-edit its shared stages.
- Branches: feature|bugfix|chore/<reference>-description, targeting `dev`.
- Every source file starts with a header comment saying what it is for; keep it accurate when you change the file. `npm run map:check` fails the build if one is missing. (TS/TSX: a leading `/** ... */` block; Rust: `//!` lines. The map shows its first paragraph, so lead with what the file is for and what it exports that others use; tests get one line naming what they cover.)
- Native calls stay in packages/editor/src/platform/ (import it as `@gonq/editor/platform/...`). Between apps/desktop and packages/editor only package imports are allowed, never `../../packages/...` (npm run boundaries:check). The web build never diverges from desktop in UI: never hide or disable UI by platform; a platform function throws a clear error (shown in the error banner) when the browser can't do an action.
- All text editing (typing, clipboard, history, Enter/list continuation, IME) is CodeMirror's own: Gonq code in packages/editor/src/editor/ only adds decorations, widgets and app integration.
- Menus and shortcuts come from the command registry. To add a menu item, shortcut or menu, add or edit `packages/editor/src/features/<feature>/index.ts` (auto-loaded) with `defineCommand({id, menu, group, order, label, shortcut?, enabled?, run})`; add `contextMenu: {group, order}` to also list a command in the editor's right-click menu (with or without `menu`); if `run` needs something new, add it to `CommandContext` (packages/editor/src/commands/context.ts) and fill it in apps/desktop/src/App.tsx. Never edit apps/desktop/src/components/MenuBar.tsx or add MenuBar props, and never add a keydown handler: shortcuts are bound from `shortcut`. Keys CodeMirror owns are shown with `hint`, not bound. Feature modules never import `isTauri` (nothing is hidden or disabled by platform).
- Comment shortcuts: Alt+M (the `Add Comment` command, shown in the right-click menu too; Alt alone, read from `event.code` so macOS Option works, ignored on key repeat, never with Ctrl/Shift/AltGr) adds a comment at the selection or caret, or focuses the draft already open; Ctrl/Cmd+Enter saves in the new-comment, reply and edit boxes (once per body, ignoring IME and repeat). The boxes and buttons carry a tooltip and `aria-keyshortcuts`. Alt+M collides with no other registered shortcut (the registry throws on duplicates).
- The navigator's Refresh (button beside the folder/repo name, always rendered, disabled with nothing open or while listing; View > Refresh Navigator, no shortcut) re-lists in place for local, ssh:// and github:// roots, keeps expanded folders, and switches to the default branch (via App's changeBranch, which warns about unsaved changes) when the open branch was deleted. No timers or watchers.
  User guide: docs/navigator-refresh.md. Tests: apps/desktop/src/components/NavigatorRefresh*.test.tsx (tree, ssh, GitHub; DOM-node identity is what proves scroll/expansion/highlight survive, since jsdom does not scroll), apps/desktop/src/features/view/refreshKeepsTabs.test.tsx, apps/desktop/src/features/github/refreshDeletedBranch.test.tsx.
- packages/editor/src/platform/bindings.ts is generated (tauri-specta) from the one command list, `gonq_core::plugin::commands` in crates/gonq-core/src/plugin.rs; never edit it. The commands are the Tauri plugin `gonq` (`.plugin(gonq_core::init())`, invoked as `plugin:gonq|<name>`; only take_launch_paths stays in the desktop app). To add a command: add it to `plugin::commands` (with `#[specta::specta]` on it, `specta::Type` on its types) and its name to `command_names::COMMANDS` (build.rs generates its permission; also add `allow-<name-with-dashes>` to crates/gonq-core/permissions/default.json, a test fails otherwise), then regenerate with `cargo test -p gonq export_bindings` and commit the file. Nothing imports it yet.
- Components use theme tokens only (styles/tokens.css; `.dark` on <html> swaps them); the logo is never recoloured.
- packages/editor/src/agent-skill/SKILL.md stays in step with packages/editor/src/comment-threads/README.md.

## Test Framework
Vitest + jsdom + React Testing Library (`npm test` runs both workspaces: apps/desktop and packages/editor, each with its own vite.config.ts and src/setupTests.ts; the desktop one imports the package's). Browser tests: Playwright in e2e/ (opt-in, `npm run test:e2e`).
- New App-level tests go in a per-feature file next to the feature (e.g. apps/desktop/src/features/<x>/<x>.test.tsx or apps/desktop/src/components/<X>.test.tsx; a test that does not need App/MenuBar/renderApp lives with its module in packages/editor) and render the app with `renderApp()` from apps/desktop/src/testing/renderApp.tsx (with `menu()` / `openDocument()`), not by copying another file's setup.
- New Playwright tests go in `e2e/<feature>.spec.ts`, not appended to e2e/smoke.spec.ts.
- e2e/smoke.spec.ts and apps/desktop/src/App.edit.test.tsx are frozen except for fixes.
- Before reading the DOM of a bare EditorView call `settleView(view)` (`settleEditors(root)` for App/dialog tests; `shownText` already does): CodeMirror parses with a 20 ms budget, so under load the tree is partial.
